## Ce que j'ai codé
### `backup.sh`
Un script automatisé de sauvegarde qui prend un nom de dossier en paramètre, vérifie sa validité, génère un timestamp au format `YYYYMMDD`, compresse récursivement le dossier dans un fichier `.zip` daté de manière totalement silencieuse, et affiche un retour utilisateur propre.

```bash
#!/bin/bash
# backup.sh - Sauvegarde un dossier en zip daté

# 1. Vérifier qu'un argument est fourni
if [ -z "$1" ]; then
  echo "Usage: ./backup.sh <dossier>"
  exit 1
fi

DOSSIER="$1"

# 2. Vérifier que le dossier existe (attention aux espaces dans les crochets !)
if [ ! -d "$DOSSIER" ]; then
  echo "Erreur: $DOSSIER n existe pas"
  exit 1
fi

# 3. Date au format YYYYMMDD
DATE=$(date +%Y%m%d)

# 4. Nom du zip
ZIP_NAME="${DOSSIER}-${DATE}.zip"

# 5. Créer le zip silencieusement
zip -r "$ZIP_NAME" "$DOSSIER" > /dev/null

echo "Sauvegarde créée : $ZIP_NAME"
```

## Observations
- **Sensibilité de la syntaxe Bash** : Le langage Bash n'est pas un langage de programmation classique ; c'est un interpréteur de commandes extrêmement pointilleux sur la ponctuation et les espaces. Une seule espace manquante ou en trop change radicalement l'interprétation d'une ligne.
- **Environnements WSL épurés** : Sur une distribution Linux fraîchement installée (comme WSL), des outils de base comme `zip` ne sont pas pré-installés. Il faut penser à mettre à jour les dépôts (`sudo apt update`) avant d'installer un paquet.
- **Prise en main de Nano** : Utilisation de l'éditeur de texte en console, gestion de l'écriture des modifications (`Ctrl + O`), validation du nom du fichier (`Entrée`) et fermeture sécurisée de l'éditeur (`Ctrl + X`).

## Ce qui m'a bloqué
- **Espaces interdits autour du `=`** : J'ai écrit `DOSSIER = "$1"` au lieu de `DOSSIER="$1"`. Bash tentait d'exécuter `DOSSIER` comme une commande système indépendante.
- **Espaces obligatoires dans les crochets `[ ]`** : L'oubli de l'espace avant le crochet fermant (`if [ ! -d "$DOSSIER"]; then`) a levé une erreur `missing ']'` car Bash a besoin de séparateurs clairs pour interpréter la commande de test.
- **Permissions refusées (`Permission denied`)** : Tentative d'exécution directe du script sans avoir préalablement déclaré le fichier comme exécutable pour le système. Résolu avec `chmod +x backup.sh`.
- **Utilitaire manquant** : Erreur `zip: command not found` résolue en installant le paquet manquant avec `sudo apt install zip`.

## Ressources & Pièges à éviter (Veille du jour)
-  **Variables non quotées** : Toujours entourer les variables de guillemets doubles (ex: `"$DOSSIER"`). Sans cela, si un dossier contient un espace dans son nom (ex: `Mon Projet`), le script plante en interprétant l'espace comme un séparateur d'arguments.
- **L'erreur du `chmod 777`** : Donner tous les droits d'écriture/lecture/exécution à tout le monde est une faille de sécurité majeure. Il faut préférer `chmod +x` ou des droits restrictifs comme `700` ou `755`.
- **Ordre des redirections** : La redirection d'erreur `2>&1` doit toujours être placée *après* la redirection standard. Écrire `command > fichier 2>&1` est correct, alors que `command 2>&1 > fichier` renverra quand même les erreurs sur l'écran.
