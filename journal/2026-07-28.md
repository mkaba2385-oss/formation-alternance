# Jour 12 - Python idiomatique

**Date** : 2026-07-28  
**Durée effective** : 4h00

## Ce que j’ai appris

j'ai découvert comment écrire du code Python de manière plus "pythonique", c'est-à-dire en utilisant les bonnes pratiques propres au langage au lieu de reproduire des habitudes venant d'autres langages comme Java ou C.

J'ai appris à utiliser les **compréhensions** (`list`, `dict` et `set`) pour créer des collections de manière plus concise et plus lisible. J'ai également vu comment ajouter des conditions directement dans une compréhension.

J'ai étudié les **générateurs** avec le mot-clé `yield`. Contrairement à une fonction classique qui retourne toutes les données d'un coup, un générateur produit les valeurs une par une. Cela permet de traiter de très grandes quantités de données sans consommer beaucoup de mémoire.

J'ai découvert plusieurs fonctions intégrées très utiles comme `enumerate()`, `zip()`, `sum()`, `max()`, `min()`, `sorted()`, `any()` et `all()`. Elles permettent souvent de remplacer des boucles longues par des solutions beaucoup plus simples.

J'ai également appris le **déballage (unpacking)** avec `*` et `**`, ainsi que l'utilisation des **f-strings** pour afficher des variables de manière plus moderne et plus lisible.

Enfin, j'ai retenu plusieurs bonnes pratiques du Zen de Python : privilégier un code simple, explicite et facile à lire.


## Ce que j'ai codé

- ** script_non_idiomatique.py ** : script contenant plusieurs mauvaises pratiques Python comme l'utilisation de `range(len(...))`, les boucles avec `append()` et les comparaisons inutiles avec `True`.

- **script_idiomatique.py** : réécriture du script_non_idiomatique.py en utilisant les bonnes pratiques Python comme les compréhensions, `zip()`, `sum()`, `max()` et les f-strings afin d'obtenir un code plus simple et lisible.

- **generateurs.py** : script regroupant un générateur infini de nombres premiers, un context manager pour mesurer le temps d'exécution, une fonction `chunk()` en mode lazy et un exemple de traitement d'un gros fichier sans charger toutes les données en mémoire.


## Ce qui m'a bloqué

Au début, j'avais tendance à continuer d'utiliser des boucles `for` avec `range(len(...))`, car c'est une habitude que j'avais prise auparavant. J'ai compris qu'en Python, il est préférable d'utiliser directement `zip()` ou `enumerate()` lorsque c'est possible.

J'ai également eu besoin de bien comprendre le fonctionnement de `yield`, car un générateur ne fonctionne pas comme une fonction classique avec `return`.

La compréhension de certaines fonctions comme `max()` avec le paramètre `key` ou encore le fonctionnement des context managers m'a demandé un peu de pratique avant de bien les maîtriser.
