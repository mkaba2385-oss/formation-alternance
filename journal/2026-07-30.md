# Jour 14 - Typage moderne en Python

**Date** : 2026-07-30
**Durée effective** : 4h00

## Ce que j’ai appris

Aujourd’hui, j’ai appris à utiliser le typage moderne en Python grâce aux **annotations de types** (*type hints*).

J’ai compris que les annotations de types ne modifient pas l’exécution du programme, mais qu’elles permettent :

* d’améliorer la lisibilité du code ;
* de mieux documenter les fonctions et les classes ;
* de détecter certaines erreurs avant l’exécution grâce à des outils comme `mypy`.

J’ai travaillé avec les types de base :

* `str`, `int`, `float`, `bool` ;
* `list`, `dict`, `set`, `tuple` ;
* les valeurs optionnelles avec `str | None`.

J’ai également découvert plusieurs notions avancées du typage en Python :

* `TypedDict` pour définir des dictionnaires avec une structure précise ;
* `TypeVar` pour créer des fonctions génériques ;
* `Generic[T]` pour créer des classes réutilisables avec différents types ;
* `Protocol` pour définir des contrats que certaines classes doivent respecter ;
* `Self` pour typer les méthodes qui retournent une instance de leur propre classe.

J’ai appris à configurer et utiliser `mypy` avec le mode strict afin de vérifier automatiquement la qualité du typage dans un projet Python.

J’ai également compris la différence entre :

* un générique (`Repository[T]`), qui permet de créer du code réutilisable avec plusieurs types ;
* un protocole (`Serializable`), qui impose un comportement commun à plusieurs classes sans nécessiter d’héritage direct.

### `repository.py`

J’ai créé un système de repository générique utilisant les fonctionnalités avancées du typage Python.

Le script contient :

* une classe générique `Repository[T]` capable de stocker différents types d’objets ;
* les méthodes :

  * `add()` pour ajouter un élément ;
  * `get()` pour récupérer un élément ;
  * `list()` pour obtenir la liste des éléments ;
  * `delete()` pour supprimer un élément.

J’ai également créé un `Protocol Serializable` définissant un contrat avec :

* `to_dict()` pour convertir un objet en dictionnaire ;
* `from_dict()` pour reconstruire un objet depuis un dictionnaire.

Plusieurs classes respectent ce protocole :

* `Person` ;
* `Product`.

J’ai aussi créé une classe `Animal` afin de tester certains comportements et erreurs de typage avec `mypy`.

Enfin, j’ai développé une fonction `save_to_json()` permettant d’enregistrer au format JSON les objets respectant le protocole `Serializable`.

## Ce qui m’a bloqué

J’ai rencontré plusieurs difficultés lors de l’utilisation des fonctionnalités avancées du typage Python avec `mypy`.

Les principales difficultés étaient :

* la différence entre `list[Serializable]` et `Sequence[Serializable]` ;
* la compréhension de l’invariance des listes en Python ;
* l’utilisation correcte des `Protocol` avec une majuscule ;
* le typage des données provenant de dictionnaires utilisant `dict[str, object]` ;
* l’utilisation de `cast()` pour aider `mypy` à comprendre certains types ;
* la compréhension du rôle de `TypeVar` et de `Generic[T]`.

J’ai également dû comprendre pourquoi certaines classes étaient acceptées par `Repository[T]` mais refusées par `save_to_json()`.
