# Jour 18 - Les principes SOLID

**Date** : 2026-08-05
**Durée effective** : 5h00

## Ce que j’ai appris

* **Le principe d'inversion des dépendances (DIP - SOLID)** : apprendre à séparer les services métier des services externes (SMS, météo, base de données) en utilisant des interfaces (`ABC`, `Generic[T]`).
* **Le pattern Strategy et les routeurs** : créer un routeur qui choisit automatiquement le bon fournisseur SMS selon le numéro de téléphone, avec un système de secours (fallback). J'ai aussi appris à rendre les règles d'alerte météo faciles à modifier sans changer le reste du code (principe OCP).
* **Les patterns Repository et Factory** : séparer l'accès aux données du reste de l'application et créer automatiquement les bonnes dépendances selon l'environnement (`dev` ou `prod`).
* **Les tests unitaires et les mocks** : tester la logique métier sans utiliser les vrais services externes grâce à `MagicMock`.

## Ce que j'ai codé

### Exercices sur les principes SOLID

* **`sms_router.py`** : création de l'interface `SmsProvider` et d'un routeur SMS (`SmsRouter`) qui choisit automatiquement le bon fournisseur selon le numéro de téléphone, avec un système de secours en cas d'échec.
* **`weather_avant.py` et `weather_apres.py`** : refactorisation du service météo en séparant les règles d'alerte (`HeavyRainRule`, `HeatwaveRule`, `StrongWindRule`) avec le pattern Strategy afin de respecter les principes OCP et SRP.

### projet Sini


* **`src/sini/repositories/base.py`** : création de l'interface générique `RepositoryInterface[T]` qui définit les opérations de base du repository (ajout, recherche, suppression, récupération, etc.).
* **`src/sini/repositories/memory.py`** : développement de `InMemoryParcelleRepository`, qui stocke les parcelles dans un dictionnaire Python pour les phases de développement et les tests.
* **`src/sini/services/parcelle_service.py`** : refactorisation de `ParcelleService` en utilisant l'injection de dépendances pour le repository, le service météo et le service SMS, afin de mieux respecter les principes SOLID.
* **`src/sini/factories/service_factory.py`** : création de la classe `ServiceFactory` pour instancier automatiquement les bonnes dépendances selon l'environnement (`dev` ou `prod`).
* **`main.py`** : création d'un script de démonstration permettant de gérer le cycle de vie complet d'une parcelle (création, consultation, modification, suppression) et de déclencher une alerte météo par SMS lorsque les conditions sont remplies.
* **`tests/test_repository.py`** : écriture de tests unitaires avec `pytest` pour vérifier le bon fonctionnement du repository en mémoire.
* **`tests/test_service.py`** : écriture de tests unitaires pour `ParcelleService` avec `MagicMock` afin de tester la logique métier indépendamment des services externes.
